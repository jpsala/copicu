## Model

- Each clip belongs to exactly one place: Root (`folder_id NULL`) or a folder. Existing rows migrate to Root. Inbox, marks, tags (including `/` in tag labels), Saved searches and Capture modes remain orthogonal. Saved searches only filter; Capture modes continue applying explicit tags and never choose folders.
- Folder names are non-empty path segments, unique case-insensitively among siblings (including Root siblings); reject `/`, control characters and cycles. Identity is a stable numeric ID. Display full paths are derived from ancestors, updated by rename/reparent, and used for quick switching and completion. Children and direct clip counts are exact, not loaded-page estimates.
- A folder feed contains its direct clips; Root shows only unfiled clips. A separate All history tree entry shows every clip. Search applies inside the current feed scope, including paginated results, counts, Find and applied snapshots; changing folder invalidates the previous cursor, selection, pending search request and refresh, while preserving the applied filter and editor draft. Navigation reloads the applied filter within the new scope; an unapplied draft retains its Realtime/Enter policy. Folder search syntax `folder:"Full/Path"` and `folder:/` resolves exact path/Root in Rust. A typed `/` opens folder completion at the caret; accepting inserts a quoted `folder:` clause; unaccepted `/` stays literal. `#` remains tags. Sidebar scoping uses a stable folder-ID filter, not a tag conversion. Explicit folder clauses intersect current scope; users can select All history to search globally.
- Updated by JP on 2026-10-04: dedupe by content hash is scoped to the destination folder, including Root. Equal content in other folders is an independent item and stays there. Capture modes still apply their explicit tags. The [folder deduplication contract](../016-shared-clipboard/folder-deduplication.md) supersedes the original global rule.

## Capture destination

- Navigation and destination are separate. New clipboard captures go to Root by default; user explicitly arms the active folder or Root as destination. Switching folders disarms the destination; hiding/reopening picker retains it in the running session, but a process restart returns to Root. Destination is host-owned transient state so hidden clipboard watcher and image/text capture see the same choice. Manual new item uses the same destination; duplicates are reused only inside that destination. A visible picker indicator distinguishes active destination from browsing.

## Folder operations

- Create, rename, move/reparent and delete folders; move one clip or current explicit selection to another folder/Root by context action or by dragging a feed row onto its tree destination. Dragging an explicitly selected row moves the entire selected set; dragging another row moves only that row. Folder and Root drop move immediately without confirmation and refresh the feed/counts. All history is not a destination. No cycles, no accidental subtree flattening. Menus are keyboard-accessible and expose Root as a destination. Narrow picker keeps a collapsible overlay tree rather than shrinking the feed into unusability. Its fold button sits at the sidebar's right edge; when collapsed, a compact reopen button shares the existing search-filter strip. Quick switch uses local `Ctrl+P`, after shortcut collision audit; `Ctrl+K` remains command palette. Shortcut hints use tooltips rather than persistent inline keycaps.
- Deletion has two independent choices in a confirmation dialog every time. Direct clips: retain (move to Root) or delete. Descendant folders: retain (reparent immediate children to deleted folder's parent; clips stay in those folders) or delete entire subtree. If descendants are deleted but clips retained, **all** subtree clips move to Root. Show exact affected clip/folder counts before confirmation. Defaults in Settings are retain clips and retain subfolders, editable per deletion without changing Settings. Database transaction covers folders, clips and counts; blobs for deleted image clips are removed only after commit. Cancel is inert.
- Foldered clips are excluded from automatic retention, like Inbox and marked clips; the configured count applies to ordinary Root clips. Moving an unmarked non-Inbox clip to Root makes it eligible on the next pruning pass; the menu's move dialog warns about this, but drop is immediate. Moving Inbox clips never removes Inbox protection.

## Keyboard/focus

- With focus in the feed (not CodeMirror editor), `Left` moves into the tree. Tree `Up/Down` select the visible folder and update its feed; `Left` contracts or selects its parent; `Right` expands or moves to the first child, then enters the feed from a leaf; `Enter` opens the folder and `Shift+F10` opens its context menu. Typing while feed focused focuses scoped search. A plain row click or click outside the rows clears the prior explicit group; `Ctrl`/`Shift` clicks and checkboxes build explicit groups. Keyboard navigation can move current independently without clearing a group. In query CodeMirror, arrows, Home/End, selection and caret behavior retain editor ownership, except existing deliberate Up/Down feed navigation outside an open completion.
- Tree collapse/reopen preserves current folder and in-process destination. The current browsing folder is a compact switchable scope chip in the search-filter strip, including when the tree is collapsed; armed capture destination has a distinct indicator there. No separate browsing or folder-toggle rows consume feed height. Context menus and confirmations stay within the main picker surface and restore focus to their invoking control.
