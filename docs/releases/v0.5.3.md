# Copicu v0.5.3: Account And Device Linking

This cut adds browser sign-in, device approval and encrypted recovery for shared
clipboards. To use sharing between PCs, configure an accessible private HTTPS
service with OIDC and enter its service URL in Settings on each PC.

## Shared clipboards

- Sign in through the system browser. A confirmed login survives restarts and
  lost responses, including expiry of the original browser sign-in window.
- Compare the complete device fingerprint before approving another PC on the
  same account. HPKE transfers authorized clipboard keys to approved devices.
- Keep device approval, clipboard connections and native effects separate.
  Linking a PC does not connect clipboards, send old clips or enable clipboard
  writes or Actions. Send and receive remain explicit, independent opt-ins.
- Generate a recovery code explicitly and retain an encrypted key snapshot in
  the private service. Recovery requires account sign-in and the code; it retires
  previous devices and marks affected clipboards for key rotation.
- Retire or relink a PC while preserving its local copies and delivery receipts.
  Revoked devices lose access; relinking requires approval and keeps previous
  connections paused until explicitly resumed.
- Windows installation and updates close only the executable being replaced,
  preserving development and test copies running from other directories.
- Keep sign-in, pending approval, recovery and device management in Settings.
  The clipboard selector preserves its draft while linking is required.

## Verification and scope

Local checks with synthetic data passed: 382 Rust tests, with one benchmark
ignored; 50 Bun service tests; 26 renderer checks; and five native Windows UI/host
cases using three fresh profiles. The native cases cover linking, approval,
encrypted delivery, service restart and recovery. Detailed results and limits
are in [identity acceptance](../../specs/016-shared-clipboard/identity-acceptance.md).

The signed Windows NSIS was built offline and its extracted x64 GUI executable
verified. Three release checks passed: startup/version/native IPC, the normal
Sharing setup UI and strict rejection of HTTP. The same installer was installed
locally; its executable hash matches and the same checks pass with a new
synthetic profile. The five full identity cases above used a debug build.

Google sign-in and a deployed HTTPS service have not yet been verified. Service
activation awaits specific approval of Google terms/OAuth credentials, DNS and
the pinned Bun image. Testing between two physical PCs remains pending.
Local synthetic checks do not establish those results.
