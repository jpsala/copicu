# Copicu v0.5.4: Shared Images

Shared clipboards can send and receive text and PNG images. Images retain their
type, thumbnail and transparency when saved or copied.

An older client can reject a whole delivery page containing a large image and
delay later text publications. Update the service and both PCs before sending
images.

## Changes

- Send a new local image from a connected folder, send the active Copicu clip,
  or use **Send Windows clipboard** to publish the current text or image.
- Preview received images in Sharing history and receptions, save them to a
  local folder and copy them manually to Windows.
- Apply the existing encrypted queue, deduplication, pause and revocation rules
  to images. Connecting does not publish old clips; received or imported images
  are not sent back automatically.
- Keep automatic Windows updates optional and limited to live arrivals. Delayed
  and recovered images remain available for manual copy. Reception Actions
  continue to process text.
- Accept PNG payloads up to 25 MiB and 4096 × 4096 pixels. Corrupt, unsupported or
  oversized images are rejected before a Windows write. File transfer remains
  outside this cut.
- Use the internal Sharing service address during normal sign-in, with its URL
  available in connection-error diagnostics. Show an explicit confirmation when
  moving a clipboard's existing reception to another local folder.

## Verification and scope

Local synthetic checks passed: 388 Rust tests, with one benchmark ignored;
48 Bun checks across four service test files; and 24 renderer checks. The Windows
native-image harness passed image/alpha round-trips and clipboard fences. These
results cover local implementation and do not establish image transfer between
two physical PCs.

JP reported successful manual text delivery in one direction between his PCs.
The signed Windows installer and updater signature are verified. Five checks
on its exact payload passed with two synthetic profiles, covering image delivery,
pixels and alpha, previews, provenance, deduplication and restart persistence.
Physical image transfer between two PCs remains to be accepted after both update.

Account-wide key custody and linking without PC approval still require a user
decision. Authenticated admission is implemented locally and has not been
enabled in Google or production; this update does not claim that rollout.
