# Copicu v0.5.11: Faster picker loading and isolated reads

## Changes

- Remove a fixed wait from picker hotkey activation and coalesce show/focus/visibility refreshes instead of repeating the same queries.
- Show the fresh first page before auxiliary catalogs; retain the existing stale-content mask, selection guards and filter-lock behavior.
- Use the existing tag index in hierarchical counts, preserving distinct clips and filter semantics. Reduce virtualized overscan and avoid unnecessary catalog-driven renders.
- Read feed refreshes and pagination through one independent read-only WAL connection. A bounded worker queue replaces obsolete refresh/page requests without interrupting the writer or a newer read.
- Keep counts, rows and match evidence coherent within each read transaction; release the transaction before thumbnail I/O. Validate renderer session/generation and native window ownership. Feed requests are capped at 1 MiB serialized, with explicit errors rather than truncation; this is not a new clip-size limit.
- Preserve the existing non-feed paths for scripts, marked-item actions, AI planning, catalogs and retained-row preview refresh. No SQLite migration, new runtime dependency, FTS, persistent cache, retention change or paste-delay change is included.

## Verification and limits

The implementation passed 435 Rust tests (four opt-in benchmarks ignored by the
normal suite), four client unit tests and all 588 renderer cases across the
recorded runs (two opt-in screenshots omitted). One renderer case encountered a
browser JS-load `ERR_NO_BUFFER_SPACE` and passed 3/3 unchanged with one worker.
Eleven native Win32 cases and five real reader IPC checks passed on an isolated
build, including external window → hotkey → global typing into visible Search.
Paste was not executed and no real clipboard/profile data was used for testing.

Synthetic release storage comparisons show substantially less waiting behind a
writer. These are not native hotkey-to-paint timings, a promise for every query,
or measurements of another PC. Rare searches, large images/context, retention,
and total idle memory/CPU remain separate work. JP reported a positive perceived
speed improvement on the local synthetic build; that is not acceptance on other
machines.

The package will use the existing updater trust root. Updater signing is not
Windows Authenticode or a guarantee against SmartScreen warnings. Optional scripts
and AI still use the existing Node.js runtime on PATH; this installer does not
install Node. Normal clipboard use does not require it.
