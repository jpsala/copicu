# Copicu v0.5.2-rc.1: Local Sharing And Folder Controls

This Windows release candidate adds opt-in shared clipboards and a common folder
tree across the picker and editors. Sharing and SSE have been validated locally
with synthetic profiles and real Copicu processes. A hosted HTTPS service, human
account setup, recovery and acceptance between two physical PCs remain pending.

Stable/latest remains v0.5.1; the candidate application and installer use the
internal core version 0.5.2. Sharing still needs explicit local provisioning.

## Shared clipboards

- Select or create a shared clipboard from a folder or All history, then choose
  send, receive or both directions. Sending and receiving pause independently.
- Pause either direction or resume both from the tray. The global sharing pause
  also suspends catalog transport; directional pauses keep the catalog active.
- Browse shared history without automatically importing clips or producing
  receipts. Explicitly connected reception preserves deduplication and avoids
  echoes. Connecting or resuming does not send old local clips.
- Manage resources, access and invitations through the configured local control
  service. SSE refreshes open or hidden Library, selector and Settings surfaces;
  reconnect reconciles the authorized catalog.
- Preserve connections, selection, focus and drafts when a resource is retired
  or access is denied. Controls for an unavailable resource remain disabled.
- Use shared publication and reception APIs from Actions with explicit
  capabilities and channel authorization. Queued publication and confirmed
  delivery remain separate states.

## Folder controls

- Use a compact folder tree in metadata, the content editor, new clips and move
  dialogs. Filtering retains matching folders and their ancestors.
- Choose with Enter, double-click or the confirmation button; create a relative
  path inline beneath the selected parent.
- Save folder creation and clip changes atomically. Cancel and Undo leave no new
  folders; moving a selection preserves each clip's tags unless changed explicitly.

## Fixes and packaging

- Reject stale sharing snapshots after identity or pause changes; cancel denied
  SSE streams without treating denied access as a fallback condition.
- Wake delivery sync with minimal publication hints while retaining leases,
  receipts, deduplication and explicit native effects.
- Keep synthetic development executables in Cargo examples, outside distribution.
- Replace an existing same-version Windows installation reliably when the
  installation helper is explicitly invoked.

## Verification and scope

- Shipping Rust library: 379 tests passed, one benchmark ignored.
- Desktop/narrow renderer: 494 tests passed, two opt-in captures skipped. The
  broad run passed 490; the four checks of menu order/filter-strip controls passed
  after their assertions were updated for the new sharing controls.
- TypeScript/model tests: 56 passed. Node regression suites: 83 passed.
- SSE has local HTTP/WebView2 evidence for lifecycle, denied/unsupported,
  cancellation, open/hidden surfaces and publication hints. Native interaction
  was verified separately with synthetic Windows profiles.
- The exact NSIS payload passed ten publication and thirteen lifecycle cases
  through real WebView2 IPC with fresh synthetic profiles: burst delivery,
  pause/resume, late snapshots, fallback, cancellation, restart and denied access.
- Updater signature verifies against the configured trust root; manifest
  version/URL/signature match. The extracted x64 payload and bundled resources
  are verified. The same NSIS was installed locally; the installed executable
  matches its payload byte for byte and passed the ten publication cases again
  with fresh synthetic profiles. These repeats are not extra distinct cases.
- Computer Use in the installed app verified the new-clip form, folder tree,
  inline creation and cancellation. No clipboard/paste acceptance is claimed
  for this brief UI check. Detailed evidence is in
  [local acceptance](../../specs/016-shared-clipboard/local-acceptance.md#candidata-firmada-v052-rc1-2026-10-02).
